# Roadmap

Living memory of the project. Single source of truth for scope, order and decisions.

---

## How to read this file

- **Phase** = epic. **Task** = one Pull Request. The checkbox tracks the task.
- Task IDs (`T-01`) are **stable and never reused**. They appear in the PR title.
- `[ ]` pending · `[x]` done
- No dates, no milestones, no deadlines. Relative order only.
- Every merged task updates this file in the same PR.
- Publishing content is not a task and carries no ID. See `project.md` §12.

---

## Definition of Done

A task is done only when all of the following hold:

- [ ] `lint` passes
- [ ] `typecheck` passes
- [ ] `build` succeeds
- [ ] No leftover `console.log`
- [ ] FSD import rules respected (no boundary violations)
- [ ] Both locales render, or the change is locale-independent
- [ ] `docs/roadmap.md` updated in the same commit

Squash merge is not on the list. It is the only strategy the repository allows, so it is
a repository setting rather than a condition the author can satisfy or verify.

Decisions deliberately deferred. A task that depends on one of these **stops** until it
is resolved, and the resolution becomes a numbered entry in the Decisions Log.

| #    | Question                                                                               | Options on the table                                                                                                                                                                                          | Blocks                                                                          |

| O-02 | Localized pathnames (`/pt-BR/sobre` vs `/pt-BR/about`)                                 | Adopt `pathnames` in `defineRouting`, or keep one slug across locales                                                                                                                                         | Coupled to O-01 — only meaningful if sections become routes                     |
| O-03 | Motion library                                                                         | `motion`, `magicui`, or CSS-only                                                                                                                                                                              | T-34                                                                            |
| O-05 | How this site takes over `bernardomrl.dev`, and what becomes of the previous portfolio | (a) apex swap, previous site reachable only through its repository · (b) apex swap, previous site kept navigable at a subdomain — `v1.`, `old.` · (c) apex swap with the previous site's URLs redirected here | The cutover, and the removal of the `noindex` of D-73. Blocks no task before it |

O-01 was deferred on purpose. The route-per-section approach was designed in full and
rejected for now on maintenance grounds: it requires intercepting clicks, a `popstate`
listener to make the back button move the viewport, a pre-paint script to avoid a scroll
flash on cold entry, and a canonical tag on every duplicated route. None of that is
exotic, but all of it is bespoke behaviour that only the author can debug. Revisit once
the landing exists and the real navigation feel can be judged.

O-05 does not decide whether the previous portfolio appears in this one. It does: it is a
mature project and becomes a case study in `content/projects/`, which is ordinary T-21
scope. What is open is only whether it also stays navigable at its own address, and under
which name. `old.` is the obvious label and the weakest one — it tells a visitor the work
is obsolete before they have looked at it.
