---
title: Velite's strict mode does not exist in the config file
---

The content pipeline was configured to fail on invalid frontmatter, and for a while it
failed on nothing at all. `strict: true` sat in the config file, was read by nobody, and a
malformed document walked through the build untouched.

The mechanism is in the tool's own source rather than in its documentation. Every
command-line flag is declared with a default of `false`, and the resolver merges the two
sources with `??`. A default of `false` is not `undefined`, so the fallback never fires and
the config value is never reached. The option only ever holds what the command line gave
it.

The build scripts now carry `--strict` and `--clean` directly, and the config file says in
a comment why those two options are absent from it. A configuration key that declares an
intent it never has is worse than its absence: it reads as solved.
